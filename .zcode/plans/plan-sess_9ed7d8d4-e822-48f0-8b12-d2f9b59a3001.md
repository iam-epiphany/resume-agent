# ResumeMind RAG 系统级改造方案

## 背景与设计原则

上次失败暴露的不是单点 bug，而是四层系统缺陷：规划层靠 LLM 自由猜测（臆测排除名单、漏拆对象）、召回层只有 dense 单路（列举/术语召回 rank 39+）、选择层多 pass 特判且词法硬门挤掉高分块、生成层无纪律（前缀重复/断言知识库缺失/level-3 自由发挥）。

本次改造原则：**确定性分析兜底 LLM 决策、多路召回替代单路、配额式多样性选择替代多 pass 特判、纪律化生成、性能与可观测性同步治理**。所有改动是通用机制，不针对个案。

## 改动明细

### A. 新增确定性问题分析器 `backend/app/services/question_analyzer.py`（新文件）
对提问做确定性分析，替代 LLM 猜：
- 枚举问句检测（扩充正则：`还有哪些/除了…之外(还)有哪些/还做过哪些/哪些其他X`）
- 补集问句检测 + 排除实体提取（`除X之外`、`这三个/那三个` 等）
- 对象类别识别（项目/技能/奖项/荣誉/课程…，用于从文档清单归类）
- 已知实体解析：用 catalog 文档名与上一轮回答摘录做重叠匹配（子串/公共词重叠≥阈值），确定"那三个"指代哪些实体
- 输出 `QuestionAnalysis{enumerative, complement, excluded_entities, object_docs, keywords}`

### B. 检索规划改造 `query_planner_service.py` + `rag_service.py`
- `plan_query` 接入分析器；`enumerative` 由分析器判定（不再只靠旧正则）
- 枚举/补集问句命中时：**从文档清单确定性拆 aspect（每个对象文档一个 aspect，查询=文档名+材料表述）**；LLM 输出仅作查询措辞增强（并入确定性 aspect 的 search_queries），LLM 不再独立决定 aspect 集合
- `plan_query` 新增 `memory_context` 参数（上轮 question + answer_excerpt + 分析器解析出的已知实体），贯穿会话上下文（现在 planner 完全无上下文）
- 排除实体（如"这三个"）写入 plan，供选择层做软降权（非硬过滤）

### C. 新增关键词精确召回路径 `retrieval_service.py`
- 小库（119 块）优势：`keyword_recall(terms, limit)` 全量扫 DB chunk 快照做子串/术语命中召回，产出精确候选
- 与 dense 候选合并进 rerank；枚举场景 rerank 全量（现有机制）
- 治理"dense 对列举对象/精确术语召回弱"这一类问题

### D. 选择层重写 `rag_service.py _select_prompt_chunks`
- 统一信号：rerank 分数为唯一相关性排序；保留绝对门槛 `max(RERANK_PROMPT_THRESHOLD, MIN_CORE_RERANK_SCORE)`（防跑题，测试锁定）
- 配额算法替代 core/anchor/query/generic/forced_minimum/relaxed 六 pass：
  1. 每 aspect 至少 1 块（该 aspect rerank 最高且非重复）
  2. 每文档配额上限（新配置 `PER_DOCUMENT_PROMPT_CAP=2`）
  3. 枚举/补集场景：对象文档（非排除者优先）配额填充，直至 MIN_PROMPT_CHUNKS/容量
  4. 按 rerank 分降序、文档轮询填充（多样性）
- 移除"关键词硬门"对语义/文档风格召回块的拦截（keyword 门只保留给低分逃生通道，防跑题行为不变）
- 保留 `prompt_selection_reason` 等字段名（测试契约），行为更新同步测试

### E. 降阈重试不再整链重跑 `rag_service.py`
- relaxed 兜底（level 1）改为**复用标准阶段的 plan 与候选池，仅放宽选择门槛**（不重新 LLM 规划、不重新检索、不重新重排）——单问省 1 次 LLM 调用 + 10s+（本次失败实测 relaxed 重跑耗时≈整链）

### F. 生成纪律 `prompt_builder.py` + `answer_generation_service.py` + `rag_service.py`
- 前缀唯一化：prompt 移除"answer 必须以推测前缀开头"指令，`_apply_confidence_mode` 统一去重后 prepend 一次（治双前缀）
- 新增通用规则：不得断言"知识库中不存在某信息"，只能表述"检索到的材料中未包含"；列举类问题只列检索到的对象
- level-3 直接生成限制：无证据时只允许 persona 软信息（特质/爱好/意向），时间/机构/项目名/数字等硬事实必须明确"知识库未收录"（与 README"硬事实必须来自检索"自洽）
- 生成 prompt 附加"对话上下文"段（上轮 Q/A 摘录），提升多轮衔接

### G. 可观测性
- `_save_qa_log` 记录真实字段：answer_mode / evidence_sufficiency / retrieval_fallback_level / used_chunks / 召回文档清单（替代硬编码 0）

## 不动的契约（测试与前端锁定）
- QAResponse 顶层字段、`retrieval_fallback_level` 0-3 语义、answer_mode 枚举、SSE stage 名
- retrieval_summary 键名只增不减；prompt 格式（`【知识片段 N】来源：`）、代词消歧段、HEDGE_PREFIX 常量
- 前端不消费 retrieval_summary，无 UI 改动
