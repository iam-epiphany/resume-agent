# 人物工坊使用说明（任意简历适配）

> 材料主题：系统说明

ResumeMind 支持任意人的简历：把对方的原始材料（PDF/Word/Markdown/聊天记录文本等）
交给「人物工坊」，大模型会把它加工成符合本系统检索规范的 Markdown 知识库并自动入库，
随后即可切换为该人物进行面试问答——全链路提示词（姓名/主人公描述/礼貌转移文案）与
检索范围（文档/事实台账/问答缓存）都会随当前人物切换。

## 使用流程（管理员）

1. **登录后台** → 左侧导航「人物工坊」。
2. **确认当前人物**：页面顶部显示当前人物与档案状态（草稿/已确认）。
3. **上传原始材料**：点击「上传简历材料（LLM 加工）」，支持多文件（pdf/doc/docx/md/txt/html/jsonl，单次 ≤10 份，单份 ≤50MB）。
4. **等待转换**：系统解析材料 → 分批调 LLM 加工 → 自动入库。任务列表显示状态、生成文档数、事实数、LLM 调用次数与**加工版本**（skill 版本）。
   - 生成内容：`knowledge_documents[]`（一主题一文件、`> 材料主题：类别` 开头、单事实段落、事实/观点分离、无法确认标 `[待确认]`）；
   - `persona_profile`：人物档案（姓名/摘要/教育/意向/技能…）→ 以**草稿**状态保存；
   - `facts[]`：结构化事实 → fact_ledger（`evidence_status` 证据分级 + `review_status` 审核状态，pending 只告警不参与硬校验，每条必带 `source_file` 来源）。
5. **隐私清洗自动执行**：身份证号、手机号、邮箱、银行卡等 PII 在入库前强制脱敏为 `[已脱敏]`。
6. **确认人物档案**：在「人物档案确认」区编辑 JSON 后「保存并确认」——确认后姓名与摘要驱动提示词个性化（草稿状态不注入，避免未确认信息误导）。
7. **切换人物**：人物列表点击「切换」——问答缓存、文档快照缓存自动清空，检索/台账/提示词全部切到该人物。

## 回滚（自动入库的兜底）

转换任务完成后若发现加工结果有问题：
- 任务列表点「回滚」：删除该任务生成的全部文档与事实（原始材料文件保留在原始资料区）。
- 手动修正路径：进入「知识库」页删除/编辑对应文档，修改 `[待确认]` 标记后重跑索引。

## 安全与成本

- 工坊接口仅管理员可用（JWT）。
- 转换按批调用 LLM，受 `WORKSHOP_MAX_INPUT_CHARS`（默认 12000 字符/批）与
  `WORKSHOP_MAX_FILES_PER_JOB`（默认 10）限制；LLM 调用计入全局每日预算保险丝。
- 关键配置（.env）：`WORKSHOP_ENABLED / WORKSHOP_MODEL / WORKSHOP_TIMEOUT_SECONDS /
  WORKSHOP_MAX_INPUT_CHARS / WORKSHOP_MAX_FILES_PER_JOB`。
- 加工质量三层兜底：转换提示词强约束「数字逐字保留、不得补写」；自动事实 evidence_status 分级（pending 审核）
  不参与硬校验；任务可一键回滚。

## 加工 skill（规范驱动，2026-08-14）

转换能力封装为可复用 skill：`.agents/skills/resume-materials-workshop/`（入库，可对外宣传）。

- **单一事实来源**：加工提示词、输出 JSON 契约、版本都来自 skill 目录，后端运行时读取
  （`backend/app/services/skill_loader.py`）；修改加工规则只改 skill，不动业务代码，
  改完跑自测并提升 `SKILL.md` 的 `metadata.version`。
- **契约校验**：LLM 输出必须通过 `references/output-schema.json`（JSON Schema）校验，
  不合契约整批拒绝，不静默入库；校验由 `jsonschema` 执行（4.26.0 起为运行依赖）。
- **版本可追溯**：每次任务记录 `skill_version`，前端任务表展示。
- **离线自测**（无 LLM 依赖，改契约/提示词后必跑）：
  ```bash
  python .agents/skills/resume-materials-workshop/scripts/self_test.py
  ```
- **目录配置**：`WORKSHOP_SKILL_DIR`（默认仓库内 `.agents/skills/resume-materials-workshop`；
  Docker 镜像内置为 `/app/agents-skills/resume-materials-workshop`）。
- 附注：skill 1.0.0 迁移时修正了旧提示词中残留的双花括号转义（`{{"filename"}}` → `{"filename"}`）。

## 人物 Skill 包（2026-08-15）：把「这个人」封装成可独立调用的 Skill

转换完成（或人物档案确认/修改、任务回滚）后，系统会把该人物的全部加工产物
**确定性组装为一个完整的人物 Skill 包**（零额外 LLM 调用），在「当前人物」卡片
点击「下载人物 Skill 包（.zip）」获取：

```
persona-{人名}/
├── SKILL.md            # 回答规则 + 渐进式加载（SKILL.md 只放规则，材料按需读取）
├── facts.json          # 本人全部事实台账（evidence_status 证据分级 + review_status 审核状态）
└── references/
    ├── profile.md      # 人物档案（姓名/摘要/教育/意向/技能/项目一览）
    ├── projects/       # 项目经历（一项目一篇）
    └── *.md            # 技能/教育/荣誉/证书/自我介绍等主题材料
```

- **用法**：解压 zip 放入任意 Agent 的 skills 目录（如 `.agents/skills/`），该 Agent
  就能在用户问及此人简历/项目/荣誉时，按本人材料作答——这就是「将用户资料自动封装
  为 Agent Skill」的落地形态。
- **组装规则**（单一事实来源 = 工坊 skill）：`SKILL.md` 由
  `references/persona-skill-template.md` 模板填充占位符生成，回答规则继承工坊质量红线
  （忠于材料 / 事实分级 / 隐私不恢复 / 拒答边界）；references/ 收录该人物全部
  `> 材料主题：` 知识文档（项目经历归入 projects/）；facts.json 导出事实台账（去重，
  不新增事实）。
- **自动重建**：转换完成、档案确认/改名、任务回滚后都会重建，包内容始终与知识库一致；
  模板缺失时跳过生成（best-effort），不影响转换任务本身。
- **安全**：包内含该人物全部个人材料，下载端点 `GET /api/personas/{id}/skill-package`
  仅管理员可访问（JWT）；公开的 persona 视图只暴露文件数/版本/生成时间等元信息。

## 人物模型

单当前人物（可切换）：同一时刻只有一个 active 人物；切换时清空问答缓存与文档快照，
检索（SQLite/Qdrant）、事实台账、问答缓存签名均按 persona_id 隔离。
存量库升级零配置：默认人物自动种子并回填全部历史数据；默认人物不内置姓名（部署者可通过 DEFAULT_PERSONA_NAME 配置，或由工坊提取/创建人物时填写）。
