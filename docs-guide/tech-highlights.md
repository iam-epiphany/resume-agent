# ResumeMind 技术亮点（答辩口径）

ResumeMind 是面向"面试官 × 简历主人公"场景的问答 Agent：面试官对简历任意提问，系统结合知识库（简历/证书/荣誉/项目文档）作答。与通用 RAG 平台（Dify/FastGPT/RAGFlow 等）相比，本系统有四个工程化亮点。

## 亮点 1：置信度分级回答 + 答案自评（Self-RAG 式证据自评）

**实现**：LLM 生成时同步输出 `{answer, evidence_sufficiency, reason}` 自评结构；后端按三档分级——`sufficient` 直接实答、`partial/insufficient` 归为 hedged（分级与原因仅记录于 `qa_logs`/审计，2026-08-15 起回答正文不再附加推测前缀）、`greeting/off_topic` 走礼貌转移模板（零 LLM）。分级结果 `answer_mode` 随 API 透出（内部观测用）。

**Grounding 硬事实校验（防"自己生成、自己判断"）**：仅靠 LLM 自评存在"模型自己说证据够"的盲区。后端追加**确定性硬事实校验器**（零 LLM、纯规则）：从答案中抽取数字、日期、专名（学校/项目/奖项/证书/技术栈）等硬事实模式，与检索证据文本做归一化匹配——答案中的硬事实在证据中缺失时强制降级为 hedged 并记录缺失项；LLM 自评 sufficient + 校验通过才放行"实答"。硬事实（数字/日期/机构/证书名）因此有了证据侧的可核查锚点。

**为什么比普通 RAG 强**：普通 RAG 是"检索 → 生成"的单行道，没有"回答可信度"的显式信号——检索弱时要么硬编（幻觉）要么硬拒（体验差）。本设计把"证据充足度"变成模型显式自评 + 确定性硬事实校验 + 后端强制分级：证据不足时不会硬编事实（硬事实口径直接"材料未记录"），分级信号仅供内部审计，界面保持正式问答体验。

## 亮点 2：LLM 意图分类 + 追问补全 + fast path（认知中间层，主流 RAG Router 思路）

**实现**：一次小 LLM 调用合并完成「3 类意图分类（resume_qa/greeting/off_topic）+ 指代消解」双职责——寒暄/无关话题零检索零生成走礼貌转移，其余进 RAG 主链；分类失败保守回退 resume_qa，意图层绝不当掉任何检索机会。查询改写（LLM 生成检索式变体）在兜底链第 2 级触发。

**fast path（普通独立问题降 LLM 调用）**：简历面试的大多数问题是"明确、独立、单对象"的普通提问，逐个走「意图 LLM → 规划 LLM → 生成 LLM」成本高（DeepSeek API 延迟主导）。系统对这类问题启用确定性旁路：无上一轮对话、无指代/追问标记时，意图层用极简规则（整句问候词表 + 默认 resume_qa）跳过 LLM；规划层对非枚举/非补集/无拆解需求的问题直接构造单方面检索（原问 + 变体），跳过 LLM。**普通独立问题从 3 次 LLM 降到 1 次**（仅生成），追问/枚举/复杂问题保留完整链路。两开关 `INTENT_FAST_PATH_ENABLED`/`PLANNER_FAST_PATH_ENABLED` 可关回退。

**为什么强**：普通 RAG 对一切问题一视同仁地"检索+生成"，无关问题硬检索 → 高幻觉、高延迟。本设计把 LLM 预算花在刀刃上：问候/无关话题零检索零生成；普通独立问题 1 次 LLM、追问 2-3 次、枚举/复杂问题 3 次——2C4G 下普通问题端到端明显快于完整链路。纯 LLM 判定替代关键词表：无词表误伤（如"你好，介绍下你的项目"被整题转移为寒暄），也无领域词表维护负担。

## 亮点 3：多轮追问记忆（Dify 会话记忆思路）

**实现**：前端 localStorage 持久化 `session_id` + SQLite `conversation_turns` 表 + 进程内 LRU（24h TTL）；指代消解已并入亮点 2 的意图调用（提供上一轮摘录、LLM 自动补全），记忆层只负责轮次存取——"那怎么解决超卖的？"被补全为带上下文的完整问题后进检索。

**为什么强**：面试本质是多轮深度追问，无状态 RAG 对依赖前文的追问必然检索失败。带记忆后追问链可连续深挖，这是"面试模拟"类产品与普通文档问答的本质差异；消解与分类合并为一次调用，无额外 LLM 成本。有上一轮对话时 fast path 自动让位于 LLM 意图调用（指代消解优先），保证追问质量。

## 亮点 4：检索兜底链（降阈重试 → 改写重试 → LLM 推理）+ 简历领域枚举检索

**实现**：四级流水线——① 标准检索（宽松门槛）→ ② 降阈重试（阈值放宽、强制 min 6 块）→ ③ LLM 改写后重检索 → ④ 无检索直接生成（persona + 会话历史，hedged 分级内部记录）；`retrieval_fallback_level` 全程透出便于观测。

**简历领域结构（枚举问句不靠猜）**：知识库文档按材料主题分类（`material_topic`：项目经历/教育背景/技能专长/竞赛奖项/荣誉奖励/证书资格/求职意向），planner 注入**运行时知识库文档清单**（动态查询 Document 表，非硬编码）。枚举/补集问句（"参与过哪些项目""除了这三个还有哪些"）由确定性问句分析器识别，按对象文档逐个拆 aspect、检索查询引用文档名锚点、全量 rerank + prompt 容量放宽兜底——被列举对象全部进上下文，且不会重复已介绍对象或伪称"知识库无记录"。

**为什么强**：普通 RAG 单次检索失败即"未找到"，丢掉了面试官口语化/长尾提问。兜底链把"找不到"转化为"放宽标准再找 → 换个说法再找 → 基于简历已知信息合理推断并标注"，配合亮点 1 的自评 + 硬事实校验保证诚实不编造，覆盖刁钻提问的最坏情况且永不拒答。

## 架构取舍（诚实版）

- **检索架构**：Qdrant 仅 dense 向量（无 sparse），关键词精确召回在应用层对 chunk 快照全量扫描（小库场景足够）；"hybrid"一词在本项目指「dense 语义召回 + 应用层关键词补充 + rerank 重排」的组合，非 Qdrant Dense+Sparse 双路。小知识库（十余篇文档）下这套组合在延迟与召回间最划算。
- **检索依赖模型质量**：精确名称/数字召回依赖 embedding/rerank 语义排序 + 应用层关键词补充；枚举类问句靠确定性拆对象 + 全量 rerank 兜底覆盖。
- **LLM 依赖**：DeepSeek 外部 API，离线时降级为摘录 + 礼貌转移（功能大减）。
- **吞吐有限**：embedding/rerank 串行、全局并发 4、单机 SQLite——面向面试场景的单访客高频追问，够用。
- **推测分级的边界**：硬事实（数字/日期/机构/证书名）仍强制来自检索片段（含确定性校验），只有"组织/推断/衔接"允许适度发挥；分级仅记录于日志/审计，不向面试官展示推测标注。
