# 加工质量红线（业务规则单一事实来源）

> 本文件是「人物工坊」LLM 加工的**业务规则全文**，由后端 skill_loader 在运行时
> 拼接进 System Prompt；AGENTS.md / SKILL.md / README 只做指针，不重复抄写规则。
> 修改任何加工规则请改这里，并提升 SKILL.md 的 metadata.version。

## 忠于来源

- 姓名、时间、角色、技术、指标和成果不得补写或拔高；材料中没有的信息标 `[待确认]`，
  合理推断标 `[推断]`。
- 资料冲突时**保留冲突并指出**，不擅自选一个版本。
- 每条事实必须填 source_file（来源文件名）；来源只能来自输入材料中标注的文件名，
  **禁止编造来源**。

## 一篇一主题

- 每篇 knowledge_document 只讲一个主题，文件名即主题（`主题_文件名.md`）；
  content 首行必须为 `> 材料主题：类别`。
- 类别限：项目经历 / 技能专长 / 教育背景 / 竞赛奖项 / 荣誉奖励 / 证书资格 /
  求职意向 / 个人特质 / 自我介绍 / 综合简历；文件名前缀须与类别一致
  （如 `项目经历_xxx.md` 的类别必须是「项目经历」）。
- 每个段落尽量只陈述一个完整事实或一个「场景—方案—结果」，用具体名词，
  避免「它/这个/上述」等跨段指代；首次出现的缩写给出中文含义。

## 事实与观点分离

- 压测数字、排名、奖项等硬事实照抄原文数字，禁止估算。
- 「熟悉/精通/显著提升/零故障」等措辞必须能由材料支撑。
- 每条事实填 evidence_status 证据分级：材料明确写出→explicit；合理推断→inferred；
  材料间冲突→conflict；材料缺失无法确定→missing。禁止把推断写成 explicit。

## 隐私

- 身份证号、银行卡、手机号、邮箱、家庭住址等一律删除或替换为 `[已脱敏]`，
  绝不进入文档内容、人物档案或事实台账。

## 去噪

- 删除招聘套话、重复结论、无关源码与通用技术科普；保留能回答
  「你做了什么、为什么这样做、结果如何、还能怎么改」的信息。
